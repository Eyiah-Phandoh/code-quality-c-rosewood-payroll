# Rosewood Payroll — Net Pay Service

A small Java 21 payroll application that calculates an employee's net pay from gross hours,
overtime, tax, and deductions.

The code was originally generated by an AI assistant. It has since been analysed and refactored, and
covered by a behaviour-focused JUnit 5 and Mockito test suite. The pre-refactoring diagnosis is in
[`ANALYSIS.md`](ANALYSIS.md).

## Business rules

The inherited payroll rules are preserved:

- Gross pay = hours worked × hourly rate.
- Hours above **40** are paid at **1.5×** the hourly rate.
- Tax is a flat percentage of total gross pay:
  - gross `< 1000` → **5%**
  - gross `< 5000` → **15%**
  - otherwise → **25%**
- Net pay = gross pay − tax − deductions.
- No deduction rates are defined by the original application, so the production default uses zero
  deductions. `DeductionCalculator` is the extension point for a future policy.

All monetary values use `BigDecimal` with a scale of **2** and `HALF_UP` rounding.

## Architecture

```text
com.amalitech.training.rosewood.payroll
├── PayrollApplication       composition root and entry point
├── Demo                     CLI presentation
├── domain                   Employee, PayrollResult
├── money                    Money precision policy
├── repository               EmployeeRepository, InMemoryEmployeeRepository
├── service                  PayrollService, GrossPayCalculator,
│                            StandardGrossPayCalculator
├── tax                      TaxCalculator, TaxBand, PercentageTaxBand,
│                            BandedTaxCalculator, StandardTaxBands
├── deduction                DeductionCalculator, NoDeductionsCalculator
└── exception                domain exception hierarchy
```

`PayrollService` receives its collaborators through its constructor. Tax rules are supplied as an
ordered `List<TaxBand>`; a new band is added without modifying payroll orchestration. A band with
no upper bound must be last in that list, and `BandedTaxCalculator` rejects any other position.
The demo's sample employees are declared in `PayrollApplication`, so the repository stays free of
application data.

## Failure handling

- Null, blank, or negative payroll inputs raise `InvalidPayrollInputException`; a null employee id
  is rejected the same way at the repository boundary.
- A missing employee raises `EmployeeNotFoundException` carrying the requested id.
- Domain failures (`PayrollException` subclasses) propagate unchanged, including storage failures
  such as `EmployeeRepositoryException`.
- Unexpected runtime failures are wrapped in `PayrollCalculationException`, logged at `SEVERE`
  with the employee id, and keep the original exception as their cause. The CLI prints that cause
  instead of discarding it.

## Running

Requires JDK 21 or newer and Maven.

```bash
mvn clean test
```

Run the demo:

```bash
mvn clean compile
java -cp target/classes com.amalitech.training.rosewood.payroll.PayrollApplication
```

`clean compile` recreates `target/classes`, so the command works after a clean build.

Example output:

```text
Employee: Efua Sarpong (e1)
Gross pay: GHS 800.00
Tax: GHS 40.00
Deductions: GHS 0.00
Net pay: GHS 760.00

Employee: Kwame Owusu (e2)
Gross pay: GHS 1650.00
Tax: GHS 247.50
Deductions: GHS 0.00
Net pay: GHS 1402.50

Payroll failed: Employee not found: unknown
```

## Quality checks

```bash
mvn verify
# Coverage report: target/site/jacoco/index.html

# PIT 1.16.1 and its JUnit 5 plugin are configured in pom.xml.
# Use JDK 21: PIT 1.16.1 cannot instrument newer JDK class files.
mvn test-compile org.pitest:pitest-maven:mutationCoverage
# Mutation report: target/pit-reports/index.html
```

The plugin versions are declared as `pitest.version` and `pitest.junit5.version` in `pom.xml`, so
the fully-qualified goal uses the configured PIT version. Mutation testing is the one step that
does not run correctly on JDK 25 with PIT 1.16.1; point `JAVA_HOME` at a JDK 21 installation when
running it.

Current verification (PIT run on JDK 21):

- **2105 tests**, 0 failures, 0 errors.
- **100% line and branch coverage** across production classes: **218/218 lines, 78/78 branches**
  (JaCoCo, enforced at 1.00 by the build).
- PIT: **89 mutations generated, 89 killed (100%)**, **0 survived**, **0 with no coverage**, test
  strength **100%**. PIT's own line-coverage figure for mutated classes is **203/213 (95%)**; this
  uses PIT's line accounting rather than JaCoCo's and is not the enforced coverage gate.

Running PIT on JDK 25 produces misleading no-coverage entries because PIT 1.16.1 cannot instrument
the newer class-file version. That is a tooling limitation, not an untested presentation class.
